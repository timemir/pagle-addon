# In-game verification

An agent can't run the WoW client, but it can read what the client writes to disk. After the dev does a `/reload` or a logout and says so, an agent reads the results from the WTF folder with `scripts/read-wtf.lua`, and the dev reads nothing. #77 tried Mechanic for this and dropped it: the files hold almost everything an agent needs.

## Where the files live

The Forever beta is in `_classic_beta_` under the WoW install. On the dev's machine that's `G:\World of Warcraft\_classic_beta_`, which WSL reaches as `/mnt/g/World of Warcraft/_classic_beta_`. The live install's folder name is unknown until launch (Nov 4).

For launch night and the 1.0 tag, [launch-runbook.md](launch-runbook.md) holds the plan, and `scripts/launch.py read <step>` runs the reader below with each dev step's flags and prints only that step's sections (launch-runbook.md › The read-wtf checklist).

Under `WTF/Account/<ACCT>/` (find `<ACCT>` with `ls WTF/Account/`; skip its `SavedVariables` folder):

| Fact | File | Format |
|---|---|---|
| Lua errors with stacks | `SavedVariables/!BugGrabber.lua` | `BugGrabberDB`. The latest session is the errors whose `session` equals `BugGrabberDB.session`. Needs `!BugGrabber` installed. |
| Catch log, wallet, varieties, looks, cards, Field report | `SavedVariables/Pagle.lua` | `PagleLog` and `PagleDB` ([catch-log.md › Data](../spec/core/catch-log.md#data), [wallet-and-shop.md › Data](../spec/core/wallet-and-shop.md#data), [varieties.md › Data](../spec/core/varieties.md#data), [announcements.md › Data](../spec/core/announcements.md#data), [field-report.md › Data](../spec/core/field-report.md#data)). Pagle writes no SavedVariables before M1, so the file is missing until then. |
| Ledger | `SavedVariables/Pagle_Ledger.lua` | `PagleLedgerDB` ([ledger.md › Data](../spec/ledger.md#data)). Missing until Pagle_Ledger (M2) has run. |
| Hunts | `SavedVariables/Pagle_Hunts.lua` | `PagleHuntsDB` ([hunts.md › Data](../spec/hunts.md#data)). Missing until Pagle_Hunts (M5) has run. |
| Stats | `SavedVariables/Pagle_Stats.lua` | `PagleStatsDB` ([stats.md › Data](../spec/stats.md#data)). Missing until Pagle_Stats (M6) has run. |
| Tackle Board | `SavedVariables/Pagle_TackleBoard.lua` (its records are in `Pagle.lua`'s `PagleLog`) | `PagleTackleBoardDB` ([tackle-board.md › Data](../spec/tackle-board.md#data)). Missing until Pagle_TackleBoard (M7) has run. |
| Account CVars (`SoftTargetInteract` etc.) | `config-cache.wtf` | `SET <name> "<value>"` lines |
| Character CVars | `<realm folder>/<Name-Surname>/config-cache.wtf` | the same |
| Machine CVars | `WTF/Config.wtf`, two levels up | the same |
| Addon enable state | `<realm folder>/<Name-Surname>/AddOns.txt` | `<Addon>: enabled` or `: disabled` lines. An addon that isn't listed has its TOC's default state. |

The realm folder is `70` on the beta. Characters are `<Name>-<Surname>` folders in it (find them with `ls`). The client writes CRLF line ends and keeps the previous copy of each file as `.bak` or `.old`; the script reads only the current one.

Values that exist only while the client runs, like `C_Spell.GetSpellName(7620)` or `Pagle.API_VERSION`, aren't in any file. They stay a dev `/dump`, except the facts `/pagle dev probe` saves for launch re-verification (Dev commands, below).

## Linking the addons

The game should load the repo's `addons/*` folders, so edits go live after `/reload`. Windows: `scripts/link-addons.ps1 -AddOnsPath <AddOns folder>` junctions each folder. macOS: `scripts/link-addons.sh <AddOns folder>` symlinks each, the same way (run it again to re-point the links at another checkout or worktree; a real folder or file with an addon's name is never touched, the script stops and names it):

```sh
scripts/link-addons.sh "/Applications/World of Warcraft/_classic_beta_/Interface/AddOns"
```

### Retail UI check (macOS)

Retail shares Forever's client code, so the dev can look at Pagle's UI in the retail client, with `--retail`. Only the UI is meant for it: the game's own data and rules differ, and a spell, zone or item may be missing or other than on Forever. The repo's TOCs say `## Interface: 16001` and `## AllowLoadGameType: camelot` (CORE-R2) and can't load on retail, and the repo gets no retail TOCs. So with `--retail` each addon becomes a real folder in `Interface/AddOns` holding a symlink to every top-level entry of its `addons/<Addon>` folder but the TOC, and a generated `<Addon>.toc`: the repo's TOC with the retail interface number, `## AllowLoadGameType: standard` (retail's game type) and `dev` for `@project-version@`, under a first line that says it is generated. A `.pagle-dev-link` file marks the folder as the script's: a folder without it is never touched.

```sh
scripts/link-addons.sh "/Applications/World of Warcraft/_retail_/Interface/AddOns" --retail \
    --source /path/to/main/checkout/addons    # default: the addons/ of the checkout the script is in
scripts/link-addons.sh "/Applications/World of Warcraft/_retail_/Interface/AddOns" --unlink
```

- **The interface number** is `--interface N`, else the retail build's from the `.build.info` beside `_retail_` (`12.1.5.70575` is 120105, major × 10000 + minor × 100 + patch), else 120105 (the current value on [warcraft.wiki.gg › TOC format](https://warcraft.wiki.gg/wiki/TOC_format)). The first line it prints says which, and why. After a retail patch run it again; an out-of-date interface number makes the client list the addons as out of date.
- **Edits.** Subfolders are linked whole, so an edit inside one (`logic/`, `adapter/`, `data/`) is live after `/reload`. A new or removed top-level file or folder, or a changed repo TOC, needs the script run again, then `/reload`. The AddOns folder must exist (the client makes it at its first login, or `mkdir -p` it), and the first run's new folders appear only at the character screen, so log out to it once (PUSH-R90). The AddOns list there must have them on; the interface number matches, so "Load out of date AddOns" isn't needed.
- **`--unlink`** removes what a run made, and nothing else: the links to `--source`'s addons, and a generated folder with its TOC, shim and marker. A generated folder that holds other files, and a link to another checkout, are kept.
- **Caveats.** The generated TOCs are only in the AddOns folder, never in git; don't edit them. Anything that needs Forever's game (its zones, Fishing as it is there, Forever's data and spells) won't work on retail. Core stops on a client that isn't Forever (CORE-R4, `adapter/Core.lua`), so Pagle's retail folder also gets a generated `PagleRetailDev.lua`, listed first in its `Pagle.toc`: it sets `WOW_PROJECT_CAMELOT` to `WOW_PROJECT_ID` while Pagle's files load, puts it back as the client had it at Pagle's `ADDON_LOADED`, and prints one chat line, "Pagle: retail UI-check build (dev link) — game data is Forever's; some things won't work." The script writes it again on every run and `--unlink` removes it; it is never in the repo or a release, and no addon code changes. Nothing else in `addons/` reads either global but `/pagle dev probe`, so its check 12 still reads the retail client's own values and fails on retail, as it should. A call that isn't on retail's 12.1.5, or is deprecated there, raises a Lua error in that view: `GetWeaponEnchantInfo()` (deprecated in 12.1.0, removed in 13.0; `adapter/LiveConditions.lua` reads the lure at login, and QoL's `adapter/Lures.lua` the same) works only while the client's deprecation fallbacks are on, and `MAX_EQUIPMENT_SETS_PER_PLAYER` (QoL's gear view) may be nil. A Lua error there is the retail client, not a bug in Pagle. SavedVariables are separate from the beta's: they're under `_retail_/WTF/Account/<ACCT>/SavedVariables`, empty until the first retail login, and nothing is shared with `_classic_beta_`.
- **Reading the results.** `scripts/read-wtf.sh` reads a retail account the same way: point it at `/Applications/World of Warcraft/_retail_/WTF/Account/<ACCT>` (find `<ACCT>` with `ls`; the realm folder is the retail realm's, not `70`, so `ls` it for `--character`). The write timing below was checked on the beta; assume it for retail.

## The reader

Run it in WSL, with the Lua 5.1 from `scripts/setup.sh`. `scripts/read-wtf.sh` runs it on that Lua from any directory:

```sh
scripts/read-wtf.sh "/mnt/g/World of Warcraft/_classic_beta_/WTF/Account/<ACCT>" \
    --character 70/<Name-Surname> [--cvar <name>]... [--addon <name>]... [--catalogue <Catalogue.lua>] \
    [--item <id>]... [--huntlist <HuntList.lua>] [--eventlist <EventList.lua>] [--hunt <id>]... \
    [--stats-item <id> --area <areaID>] [--skill N] [--now T] [--expect-casts N] [--since T]
```

It prints eighteen sections, one more per `--hunt` and one more with `--stats-item`, and the exit check last with `--expect-casts`:

- **Lua errors:** the latest !BugGrabber session's errors, each with its count and stack, or `0 errors`.
- **Catch log:** `PagleLog` decoded with Core's own codec (`addons/Pagle/logic/CatchLog.lua`), so it reads entries exactly as Pagle does: the format, logId, character and entry counts, `PagleDB.global.decodeErrors`, the entries by tag, the entries the codec can't decode, repeated entry IDs, the `C1` Casts and their time span, by outcome, per character and per zone areaID, the Casts in zone areaID 0 by seq, `realm clock:` with the realm's UTC offset worked out from the latest Cast's realm minute (LOG-R49; "unknown" when no Cast read it), for placing a window in realm time, and the `B1` and `S1` entries. Then `P1:` and `U1:`, the count of Prestige and purchase entries (`none` without any), with one line per entry: a `P1`'s rank and Activity XP snapshot (0 for a pre-1.0 `P1` without one, AXP-R5), a `U1`'s good and price, each with its character and time. A log in another format than the codec's is reported, not decoded.
- **Ledger:** `PagleLedgerDB` from `Pagle_Ledger.lua`. One line when the file or `PagleLedgerDB` is missing. Otherwise, in order:
  - `projection:` the stored `lastSeq`, `logId`, `fingerprint` and `rulesVersion`. Then `logId:` whether it matches `PagleLog`'s (a different one is flagged `DIFFERS`: Core rebuilds at login), `lastSeq:` whether it equals the log's length, and `rulesVersion:` whether it is the Ledger's own (`LEDGER_RULES_VERSION` × 100 + Core's `SIZE_RULES_VERSION`, so 1202 since Fresh Water refills only after a real break: Ledger rules version 12, Core's 2; any other is flagged `DIFFERS`: Core rebuilds at login).
  - `world:` the catalogue the Ledger's world index was built from, its fingerprint, whether that is the projection's (flagged `NOT the projection's` otherwise: the computed lines then use a different catalogue than the game did), and its charted zone count. One `can't load` line instead when the catalogue doesn't load, and then nothing below is computed.
  - `state:` the Casts, Catches, XP, Coins and Species count, with the Angler Level.
  - `state curio items:` and `state trophy items:` each caught item with its Catches (`6309 ×2`), classed by the Ledger's own `ClassifyCatch`; `state other items:` only if some item is neither now. Legend items are listed in the Ledger M4 section.
  - `state Uncharted:` the Uncharted list: one line per item ID with its Catches and its Catches per zone.
  - `state zones:` one line per fished zone: its computed rank (`none` in an M2 state), whether it is charted, and its shown rank.
  - `completion:` Ledger completion, its percent, done and total, each part's "x of N" (Species, varieties as the fish with all ten, junk, treasure, trophy, zones at Master), and the Legends beside it.
  - `celebrated` lines: the highest level, Coins, Species, Species × zone pairs, zones with their celebrated rank, Species stars and family stars (the stars in all, then each one's, as `6303 ★1 ★2`), curio items and trophy items as two lists, classed as the state's are (one unclassed `celebrated items, not classed:` line when the catalogue can't be loaded), Uncharted item IDs, and Skill Milestones.

  Everything computed (the level, charted, shown ranks, completion, the classes) comes from the Ledger's own `logic/` files, over the world index built from the repo's `addons/Pagle/data/Catalogue.lua` with Core's `logic/Catalogue.lua`. `--catalogue <file>` builds it from another, such as the installed addon's `Interface/AddOns/Pagle/data/Catalogue.lua`, when the repo's has moved on. Always pass it when the dev runs a local-only build, such as the M3 exit check's Uncharted stand-in (#146 step 4): the repo's catalogue doesn't know that build's changes, so `world:` would read `NOT the projection's` and the stand-in item would be classed as the repo's catalogue has it, not as Uncharted. In such a build, make an item with no lore key of its own uncharted (a trophy weight whose family keeps another weight, a Species item that isn't the representative, or an `other` item), or also drop its lore keys: with the lore check on, an orphan `species.<id>.*` or `sub.<id>.plaque` key stops the generator (DATA-R107).
- **Ledger M4:** what M4 adds to `PagleLedgerDB`, after the Ledger section whenever `Pagle_Ledger.lua` holds one. In order:
  - `climb:` the prestige rank, the climb's own XP (the Ledger's own since the latest Prestige plus the carried XP, LED-R31), the latest Prestige snapshot the state applied (`prestigeActivityXP`, 0 before the first), the current climb's Activity XP (`max(0, total − snapshot)`, with the total the sum of `PagleDB.global.activityXP.earned`, as `Pagle.GetActivityXP()` gives it, LED-R37), the computed level with it and the peak level (60 once the rank is above 0), from the Ledger's own `ClimbActivityXP`, `Level` and `PeakLevel`. The titles below count that Activity XP too. An M2 or M3 state reads as rank 0, and a `Pagle.lua` from before M8 as a total of 0.
  - `Catch Milestones:` each one reached with its time, and the lifetime Catches.
  - `Legends caught:` each Legend item (classed by `ClassifyCatch` over the world) with its Catches and its first Catch's time, character and zone.
  - `records:` how many Species hold a Simulated Size record, of all Species caught, and how many Legends do. With `--item <id>` (repeatable), one `record of <id>` line each: a Species' or Legend item's record as length in mm, band (with Core's band name), Catch ID and `since`; `none` when it has no sized Catch yet; `not in the state` when nothing of that ID is caught.
  - `titles earned:` the title keys, computed by the Ledger's own `TitleKeys` plus the celebrated ones, in LED-R75's order (the celebrated ones only, said so, without a state or a world).
  - `active title:` `profile.activeTitle` when it's earned; `automatic, so <key>` when none is stored; a stored key that isn't earned is said so, with the automatic key it reads as.
  - `celebrated` lines: the highest level per climb (`prestige rank 0 level 60, prestige rank 1 level 4`), the prestige rank, the Catch Milestones, the title keys and the Legend items.
  - `sizes:` (#267) every Catch in `PagleLog` with a Simulated Size, decoded with Core's codec and `logic/Size.lua` over the catalogue (the repo's or `--catalogue`'s; LOG-R65–R67, LOG-R100), Legends included. `sizes by band:` each band's Catches and share. Each Catch is bounded by its Reach (ADR 0014), so no band has a share to check against: a new Angler's Catches sit in the low bands. `sizes per Species:` each Species ID (a Legend said so) with its Catches, shortest and longest length and typical length in mm. One line instead when there's no `PagleLog`, no LuaBitOp (run it through `scripts/read-wtf.sh`), the catalogue can't be loaded, or no Catch is sized. It reads the log, not the Ledger's state, so it prints even before the Ledger's first build.

  Without a world, `Legends caught:` and `celebrated Legend items:` say they can't be told from the other items.
- **Hunts:** `PagleHuntsDB` from `Pagle_Hunts.lua`, and Hunts' records in `PagleLog`. One line when the file or `PagleHuntsDB` is missing. Otherwise, in order:
  - `records:` the `A1` entries whose Module is `Hunts` (another Module's are never counted), by kind (`run`, `def`, then any other kind); `records Hunts skips:` those Hunts' own codec (`logic/Records.lua`) can't decode or doesn't fold (another kind), by seq (HNT-R150, HNT-R154). Exit-check step 2's `run` record for the slot shows in the count and in `runs:` below.
  - `projection:` the stored `lastSeq`, `logId`, `fingerprint` and `rulesVersion`, with the same `logId:` and `lastSeq:` checks as the Ledger's. `rulesVersion:` whether it is Hunts' own (`HUNTS_RULES_VERSION`, 2 since M8 Hunt Events; any other is flagged `DIFFERS`: Core rebuilds at login). `projection: none stored` instead before the first build, and then no state lines.
  - `Hunt list:` the `HuntList.lua` read, its fingerprint and its Hunts and sets; `fingerprint:` whether the stored one is the catalogue's content fingerprint plus that Hunt list's and the event pool's (`<content>+<Hunt list>+<event pool>`, DATA-R72, DATA-R98; any other is flagged `DIFFERS`: Core rebuilds at login). One `can't load` line instead when the Hunt list doesn't load, and then nothing below is computed: the Hunts are listed by ID, without where they stand or their thresholds.
  - `summary line:` "Hunts: {done} of {current} done · {n} titles", with " · {r} wagers settled" once a run is settled (HNT-R89), at the time read: the `--now` time or the reader's clock. Ladder titles count among the {n}.
  - `state:` the Casts, Coins, the count of Hunts with progress and of titles. Then one line per Hunt with progress, in Hunt-list order: where it stands (`current`, `retired <date>`, `not out until <date>`, or `not in the Hunt list`), `count`, `effort`, `sinceLast` and its tiers reached of all (`tiers 2 of 3 (1 / 10 / 40)`), with one line per reached tier: its trim, realm date, zone areaID and item ID.
  - `titles earned:` each earned set title with its date, the time it was earned at, and whether it came `from a Catch` or `from a retirement` (HNT-R23).
  - `settled:` the completed-run count; `ladder:` the steps reached of 25 / 50 / 100, one line each with its time in realm-local and server time (HNT-R148).
  - `coins:` and `xp:` Hunts' lifetime Coins and Activity XP (HNT-R110, HNT-R115), and whether `xp` equals Core's stored total for `Hunts` (`DIFFERS` with Core's otherwise: Hunts' next report sets it; `Core stores no Hunts total` before its first, AXP-R3).
  - `runs:` every known run (HNT-R150), by start, at the time read, with times in realm-local time (at the realm's UTC offset from the log's latest Cast, LOG-R49) and server time. One line per run: its run key, event, source (`r` the rotation, `p` pushed), whether it is `on`, `ahead` or `ended` at the time read (HNT-R143) and `settled <time>` when completed (HNT-R146); then its start and end; then each of its event's Hunts, in file order, with its count and tiers reached in that run (HNT-R145). A run whose event isn't in the event pool read (a pushed definition's) lists the Hunts it has progress for, without their tiers. `runs: none known` before the first run.
  - `rotation:` the fallback slot holding the time read (HNT-R152): its index and band, its bounds in server time, its pick from the event pool read (`pick none` when its band has no event), `covered by` the logged runs over it (then the run log logs nothing for it, HNT-R153) or `no logged run covers it`, and how long until it ends, when the next slot's pick comes on (exit-check step 7). `no slot before its starting point` before `ROTATION_ORIGIN`.
  - `celebrated tiers:` (each Hunt's highest tier shown) and `celebrated titles:` (HNT-R90); `celebrated runs:` each run key with its event Hunts' highest tiers shown, `settled` when its completion was shown, and `endsAt`; `celebrated ladder:` the ladder steps shown (HNT-R90, HNT-R92). Then, with a state, `celebrated: MISSING` for each reached mark (run key, Hunt and tier), settled run or ladder step that isn't in the celebrated set (its moment was never shown, HNT-R91), or `every reached mark, settled run and ladder step is in it`; a run that ended more than 30 days before the time read is left out and named on its own line, as `done` drops its entry and a rebuild raises nothing for it (HNT-R92).
  - `pins:` the pinned Hunt IDs, and those Hunts drops at its next load because they aren't current (HNT-R81).
  - `tracker.shown:`, `tracker.collapsed:`, `windowMoments:`, `showCompleted:`, `tracker.wagersCollapsed:`, `companionHint:` and `lastHintNod:` (with its time), each marked `(not saved: the default)` when AceDB left it out.

  Everything computed (where a Hunt stands, done, the summary line, the stale pins, the trims, the fingerprint Hunts hands Core, the records decoded, each run's Hunts and tiers, the rotation's slot and pick, which runs ended more than 30 days ago) comes from Hunts' own `locale/`, `data/` and `logic/` files, loaded in `Pagle_Hunts.toc`'s order over the repo's `addons/Pagle_Hunts/data/HuntList.lua`. `--huntlist <file>` reads another, such as a local-only build's or the installed addon's `Interface/AddOns/Pagle_Hunts/data/HuntList.lua`, and `--eventlist <file>` another event pool than `data/EventList.lua` (its fingerprint joins the Hunt list's, HNT-R136); `--catalogue` gives the content fingerprint. `--now T` (server time, Unix seconds) reads everything that depends on the time at T.
- **Hunt <id>:** one section per `--hunt <id>` (repeatable), right after Hunts: the Hunt's set, kind, target, window or the keys of its conditions, tiers, `since` and `retired`; whether it is current, retired or not out yet, pinned, and its celebrated tier; `progress:` its `count`, `effort`, `sinceLast`, `caught`, done and finished (HNT-R17); each reached tier with its threshold, trim, Catch ID, item ID, zone, realm date and time; and `next:` the next threshold and how many Catches it is away. One line when the ID is neither in the Hunt list nor in the state.
- **Stats:** `PagleStatsDB` from `Pagle_Stats.lua`. One line when the file or `PagleStatsDB` is missing. Otherwise, in order:
  - `projection:` the stored `lastSeq`, `logId`, `fingerprint` and `rulesVersion`, with the same `logId:` and `lastSeq:` checks as the Ledger's. `rulesVersion:` whether it is Stats' own (100 × `STATS_RULES_VERSION` + Core's `SESSION_RULES_VERSION`, so 102 in M6; any other is flagged `DIFFERS`: Core rebuilds at login). `fingerprint:` whether it is the content fingerprint of the catalogue read (the repo's `addons/Pagle/data/Catalogue.lua` or `--catalogue`'s; any other is flagged `DIFFERS`: Core rebuilds at login). `projection: none stored` instead before the first build, and then no state lines.
  - `totals:` the Casts, Catches and got away; `places:` the places counted (zones and subzones), and the scope and hit counts; `margins:` each skill margin bucket's Casts and got away (STA-R26); `characters:` each character's Casts, Catches, got away and last Skill Reading rank.
  - `Sessions:` how many Session records are stored and how many Session IDs the log's Casts carry (the two should be equal), then the last five, oldest first, each on two lines: its index and ID, its start and end in realm-local time (the realm's UTC offset read from its first Cast, LOG-R49) and in server time; then its Casts, Catches, got away, Casts per zone and skill gained, and `the log tags N Casts with it`, flagged `DIFFERS` when that isn't its Casts.
  - `latest Cast:` the log's latest Cast's zone and subzone areaIDs (`no subzone` for 0) and its effective skill, rank + mod: the `--area` and `--skill` to read an item where the dev stands, as the book does (#221 step 2). Left out with no Cast in the log.
  - `tracker:` "Show the live tracker"; `watched:` the watches, oldest first, each with its item, area, Your odds in short, its Dry spell count, its band (`no luck reading` without one) and the scope it was read in (the book's saved position is in the Books section). Each is marked as the default when AceDB left it out.

  Every reading (the watches and `--stats-item`) comes from Stats' own `locale/`, `data/` and `logic/` files, loaded in `Pagle_Stats.toc`'s order, over the catalogue read; without it, none is computed. Names show as `Item {id}` and `Area {id}`. `--skill N` is the live effective skill (rank + modifier) they are read at, so it picks the side as the game does; without it each place reads on its side with the most Casts (STA-R41), as the game does while the skill is unknown. `--now T` times the Dry spell's "{n}h ago".
- **Stats item <id> in area <areaID>:** with `--stats-item <id> --area <areaID>` (both or neither), right after Stats: `side:` and what decided it (`--skill` against the no-junk line, the most Casts, or no line); `scope:` the scope key, its Casts and the item's catches in it (and, for a subzone under 100 Casts, that its zone's is used); `state:` learning, unseen or known; `Your odds:` the entry's headline and the short form; `range:` the 95% range once known; `sentence:` the scope line or the learning or unseen sentence; one `note:` per STA-R46 sentence that applies; `Dry spell:` the Casts since the last catch in the scope, its `at` and time, and with a luck reading `P` and its band; `Dry spell text:` the entry's words; `short:` the row's short odds and Dry spell. One line when no projection is stored or the catalogue doesn't load.
- **Tackle Board:** its records in `PagleLog` and `PagleTackleBoardDB` from `Pagle_TackleBoard.lua`. One line when the file or `PagleTackleBoardDB` is missing. Otherwise, in order:
  - `records:` the `A1` entries whose Module is `TackleBoard` (another Module's are never counted), by kind (`start`, `day`, `issue`, `post`, `reroll`, then any other kind); `records the board skips:` those the board's own codec can't decode (an unknown kind, a payload it can't parse or a value out of range, TKB-R80), by seq; then the last 10, oldest first, each with its seq, its realm-local time (at the realm's UTC offset from the log's latest Cast, LOG-R49) and server time, its kind, and its boundaries (`dayStart`, `weekStart`) or its goal definition (type, kind, tier, pay, need, target and the goal's text), a `reroll` with the goal it takes down; one it skips is flagged `SKIPPED` with its payload.
  - `projection:` the stored `lastSeq`, `logId`, `fingerprint` and `rulesVersion`, with the same `logId:` and `lastSeq:` checks as the Ledger's. `rulesVersion:` whether it is the Tackle Board's own (1000 × `TKB_RULES_VERSION` + Core's `SESSION_RULES_VERSION`; any other is flagged `DIFFERS`: Core rebuilds at login). `fingerprint:` whether it is the content fingerprint of the catalogue read (`DIFFERS` otherwise). `projection: none stored` instead before the first build, and then no state lines.

- **Re-verification:** what launch re-verification checks 2, 4–7 and 10 read from the files (#262, [roadmap.md › Launch re-verification checklist](../spec/roadmap.md#launch-re-verification-checklist)). In order:
  - `check 2:` `PagleLog`'s entry count and `Pagle.lua`'s size in bytes (and MiB).
  - `check 2, 10:` the load timings Core kept at the last login made with dev mode on (`PagleDB.global.probe.timings`, Dev commands): the login's time and the log's length at load, then each mark in ms after Core's files loaded (Core's files loaded, `ADDON_LOADED`, log opened, `PLAYER_LOGIN`, `PLAYER_ENTERING_WORLD`, projections idle; `not reached` for one the login never got to, such as idle after a logout mid-rebuild); for a `/reload`, how long before Core's files loaded Core heard its `PLAYER_LOGOUT` (every addon's logout, the SavedVariables written, and the addons before Core loaded; left out after a client start); each addon loaded after Core until `PLAYER_LOGIN`, the Modules and every other addon, with its time since the one before (its files, its SavedVariables and every `ADDON_LOADED` handler; the first's includes Core's own login step 1), then `PLAYER_LOGIN`'s; then one line per projection's catch-up or rebuild (`fieldReport`, `wallet`, then each Module's): its mode, the entries applied, when it started and finished, its frames, and its longest frame against LOG-R71's per-frame budget (`OVER` past it; one that ran at once, 500 pending entries or fewer, has none to meet). `check 10:` the time from `PLAYER_ENTERING_WORLD` until every projection had caught up. The gap from Core's files loaded to `ADDON_LOADED` is mostly the client reading the SavedVariables. One line instead when no timings are stored.
  - `check 4:` the Casts whose realm minute is in the catalogue's `night` window (DATA-R36), with the first and last realm minute through the night; the Casts with no realm minute, by seq; and the realm's UTC offset each Cast's realm minute gives (LOG-R49), flagged when there's more than one (a clock change, or a wrong realm minute).
  - `check 5, 7:` the diagnostics buffer's entries by locale (LOG-R81); `check 5:` one line per hovered text and locale, with its Casts, its areas (each with its Casts) and its catches, from the P rows Core's own `ns.FieldReportPRows` builds (REP-R22); `check 7:` each entry whose zone or subzone text didn't resolve (LOG-R22), with its locale, both texts and the areaIDs stored.
  - `check 6:` the Casts per zone/subzone areaID (`12/87`), each place `FLAGGED` when its zone is 0, or its zone or subzone is an alias source (DATA-R32, never stored by LOG-R22), outside the catalogue's areas, or an area with `hasData = false` (DATA-R31); then how many places are flagged. The catalogue is the repo's or `--catalogue`'s; pass the installed addon's when the repo's has moved on.
- **CVars:** each named CVar from every file that sets it. `--cvar` defaults to `SoftTargetInteract`.
- **Addons:** each named addon's state. `--addon` defaults to `Pagle`, `Pagle_Ledger`, `Pagle_QoL`, `Pagle_Hunts`, `Pagle_Stats` and `Pagle_TackleBoard`.

AceDB leaves out of the file every value equal to its default, so a missing `decodeErrors`, `coins`, `writeUp`, `cards`, `summary`, `pending`, celebrated set, `appearance`, `goods`, `lengthUnit`, `activeTitle`, `dock.point`, `announcements.point`, `books`, `pushed`, Hunts' celebrated set (or its `runs` or `ladder`), `pins`, `tracker`, `wagersCollapsed`, `windowMoments`, `showCompleted`, `companionHint`, `lastHintNod`, Stats' `tracker` or `watched`, or the Tackle Board's celebrated set, `tracker` or `trackerCollapsed` reads as its default: 0, empty, unset or the setting's default.
- **Exit check (#75 steps 3 and 4)**, with `--expect-casts N`, the dev's Cast count: one `ok` or `FAIL` line each for N `C1` Casts, no repeated entry ID among them, none in zone areaID 0, a `B1` and an `S1` entry, `decodeErrors` 0, every entry decoding, and at least one got-away Cast (`g`). It comes last, so the verdict is the last line.

A `Pagle.lua` with more distinct strings than Lua 5.1 loads in one piece (262,143, "constant table overflow"), such as a `big20` test log's, is read in parts: each long run of string items, one per line as the client writes them, is loaded apart, still as data.

`--since T` counts only the Casts at server time T (Unix seconds) or later, so earlier sessions don't change the count; `B1` and `S1` are still looked for in the whole log, since Core writes them only when the build or the skill changes. Naming a `--cvar` or `--addon` replaces its defaults. Without `--character`, the character's CVars and addons are skipped. The script loads SavedVariables files as data in an empty environment and never runs them with globals.

Exit codes: 2 on a usage error, 1 when an `--expect-casts` check fails (a missing `Pagle.lua` fails it too), otherwise 0, whatever the files hold.

### A hand-made Pagle_Content

`scripts/pushed-content.py` writes a `Pagle_Content` folder (its TOC, with `## Interface:` and `## AllowLoadGameType:` copied from `Pagle.toc` and `## Dependencies: Pagle`, and its one data file setting `PagleContentData`) from a payload file in the grammar of [pushed-content.md › The payload](../spec/core/pushed-content.md#the-payload), such as `spec/Pagle/fixtures/content/good.txt`. Run it in WSL or macOS with the pinned Python, into the client's AddOns folder; then log out to character select once, since a brand-new folder appears in the game only there (PUSH-R90):

```sh
.tools/bin/python scripts/pushed-content.py spec/Pagle/fixtures/content/good.txt --key-id devKey --seq 1 \
    --out "/mnt/g/World of Warcraft/_classic_beta_/Interface/AddOns"
```

- **Unsigned,** as above, for the M8 exit check's step 6: the file has no `sig`, and Core ships no key anyway, so `/pagle dev content` reads `pushed content is missing: a missing field, sig.` Delete the `Pagle_Content` folder afterwards.
- **Signed with the spec's test key,** for a local-only build that adds it: add `--sign spec/Pagle/fixtures/signing/test-only-private-key.pem --key-id testKey` (and `--generated-at`, `--expires` as wanted; they default to now and a week on), and paste the entry `scripts/pushed-key.py spec/Pagle/fixtures/signing/test-key-public.pem testKey` prints into `ns.PUSHED_KEYS` in the installed `Pagle/logic/PushedKeys.lua`. `/pagle dev content` then reads `connected`, with the kinds and their counts. The test key is TEST ONLY: never commit it to `PushedKeys.lua` or ship a build holding it. A second file with a lower `--seq` than one accepted reads `a lower seq` (PUSH-R92), and one with `--generated-at` 25 hours ago reads `notRunning`.

## Protocol

1. **Ask for one action.** Tell the dev exactly what to do in the game: `/reload`, log out to the character screen, or quit. Say which one; the write timing below decides it.
2. **Wait for the dev to say it's done.** Don't read before that: the files hold the last write, not the live game.
3. **Check the write happened.** `ls -l --time-style=full-iso` on `SavedVariables/!BugGrabber.lua`: it must be newer than the dev's action, and the BugGrabber session number goes up by one with every load. Don't judge `config-cache.wtf` or `AddOns.txt` by their time: the client rewrites them only when something in them changed, so an older time means nothing changed (see below).
4. **Run the reader** and report what it prints. Quote errors in full.

Never ask the dev to open a file or read a value the reader prints.

## Write timing

Checked on beta build 1.60.1.70338 on 2026-10-13 (#78), with an account CVar (`SoftTargetIconGameObject`) and an addon's enable state as markers, reading the files after each step:

| What the dev does | `SavedVariables/*.lua` | account `config-cache.wtf`, `AddOns.txt` | `Config.wtf` |
|---|---|---|---|
| changes a CVar or an addon's state in the game | not written | not written | not written |
| `/reload` | written | written, with the change | written |
| logs out, quits, or **End task** on the app row in Task Manager (a clean close) | written | written if something changed; otherwise left as they were | written |
| kills the client (`taskkill /F`, or Task Manager's Details tab) | not written | not written | not written |
| logs in | – | – | written |

- **A `/reload` is enough.** Every step that reads CVars or addon state can say "`/reload`", not "log out".
- **A kill loses every change since the last write.** The files keep the last clean write, and the next login loads those values: the server didn't restore the CVar changed before the kill. So a leased CVar survives a crash only if a `/reload` or logout wrote it while the lease held.
- **Only non-default CVars are saved.** Setting a CVar to its default removes its line from the file. The reader reports a missing line as "not set (the client's default applies)".
- Not checked: when the character's `config-cache.wtf` is written. No character CVar changed in the test.

## The M1 exit check (#75)

The dev does everything in the game: casting, combat, killing the client, clicking popups, judging how the UI looks, and every `/reload` and logout. An agent reads the rest from the files:

| Step | The dev | An agent reads |
|---|---|---|
| every step | the `/reload` or logout | the latest BugGrabber session: no Lua error |
| 1 Fishing spell | the spell ID from `/etrace`; `/dump C_Spell.GetSpellName(7620)` | – |
| 2 30-minute stretch | all of it, and the count | – |
| 3 Read `PagleLog` | `/reload`, then log out | all of it, with `--expect-casts <the dev's count>`: the `C1` count equals the dev's count, no repeated entry IDs, no zone areaID `0`, a `B1` and an `S1`, `decodeErrors` 0 |
| 4 Got away | – | a `g` among the `C1` outcomes (the same `--expect-casts` run) |
| 5 Combat | enters combat; the key does nothing, then casts again; `/reload` after the stretch | `SoftTargetInteract` after the `/reload` equals the player's value, read before the stretch. The file can't show the value during combat. |
| 6 Crash | kills the client with `taskkill /F` (not **End task**, which closes cleanly), logs in, `/reload` | the leased CVars after the kill and after the `/reload`; the dev posts the result on #72 |
| 7 Conflict popup | sees the popup, clicks "Use Pagle", reloads, the key works | Angleur `disabled` after the `/reload` |
| 8 QoL off | disables Pagle_QoL, `/reload`, fishes, checks the Fishing page and the bindings are gone | Pagle_QoL `disabled` and the new `C1` entries after a `/reload` |

- **`--preset`** only reads the account folder. It writes a stage folder `<out>/<ACCT>/<UTC time>-<preset>/` (`--out` defaults to `~/pagle-test-logs`, outside the WTF folder): first `original/`, a byte-for-byte backup of every Pagle addon's SavedVariables file and its `.bak` there is (`Pagle.lua`, `Pagle_Ledger.lua`, `Pagle_QoL.lua`, and `Pagle_Hunts.lua`, `Pagle_Stats.lua` and `Pagle_TackleBoard.lua` once those ship), then the test `Pagle.lua` and `stage.txt` (the preset, both logIds, the character; for `boardday`, the next daily reset, for `showcase`, the reset after the last lit day's, and for `wagers`, the current fallback slot's end). When a test log is installed, the backup is copied from that test log's stage, so switching presets never backs up a test log as the real one.
- **`--install`** copies the newest stage's `Pagle.lua` into `SavedVariables/`, only when the account's `Pagle.lua` is still the one backed up, or is a test log made here (switching presets). Otherwise the backup is stale: run `--preset` again. A `boardday` test log is installed only before the next daily reset after it was made, a `showcase` one only before the reset after its last lit day's, and a `wagers` one only before its current fallback slot ends.
- **The next login is a first build.** The new `logId` makes Core rebuild every projection (LOG-R72); the Ledger empties its celebrated set and writes itself up from the test log in one Write-up section, with no moment (LED-R90, LED-R93), and so does a started Tackle Board (TKB-R84). The Catches after it are live, so the level's or the Catch Milestone's moments are raised.
- **`--restore`** puts back the backup of the stage whose test log is installed: each backed-up file byte for byte, and a Pagle file that wasn't there (a `Pagle_Ledger.lua.bak` the test play made) removed. Other addons' files are never touched. The real `Pagle_Ledger.lua` and `Pagle_TackleBoard.lua` come back with the real `logId`, celebrated set and projection, so nothing rebuilds or is written up again. It refuses while the real log is in place, so it can never put an old backup over newer real Catches.
- `--install` and `--restore` first copy every file they replace into `<stage>/replaced-<UTC time>/`, so nothing is lost, and the `.sh` refuses both while a WoW process runs. Every refusal exits 1 and changes nothing.

The stage folders hold the dev's account folder name and characters: they stay outside the repo.
